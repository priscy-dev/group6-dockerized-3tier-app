# Group 6 Fitness Tracker

A Dockerized three-tier Fitness Tracker with a React/Vite frontend, Node.js/Express API, MongoDB, automated GitHub Actions releases, and Terraform-managed AWS infrastructure.

## Application architecture

- **Frontend:** React and Vite compiled into an Nginx container. Nginx serves the site and proxies `/user`, `/api`, and `/health` to the backend.
- **Backend:** Node.js and Express provide registration, authentication, profile, and workout APIs.
- **Database:** MongoDB stores users and workouts on persistent storage.
- **Local environment:** Docker Compose starts all three services on a private Docker network.
- **AWS environment:** An internet-facing Application Load Balancer terminates HTTPS. The frontend and backend run together on a private application EC2 instance, while MongoDB runs on a separate private database EC2 instance with an encrypted persistent EBS volume.

## Run locally

Generate development-only secrets, then start the stack:

```powershell
node scripts/initialize-local-secrets.mjs
docker compose up --build -d
docker compose ps
```

Open `http://localhost:8080`. The health endpoint is available at `http://localhost:8080/health`.

MongoDB and the backend port are deliberately not published to the host. To stop the application without deleting database data, run `docker compose down`.

## CI/CD pipeline

The workflow in `.github/workflows/ci-cd.yml` performs the complete application release:

1. On pull requests, lint and build the frontend, verify the backend container build, format-check Terraform, and validate the Terraform configuration.
2. On pushes to `main` or `ci-cd`, build both application images with the same immutable short commit SHA and push both to Amazon ECR.
3. Assume a restricted AWS role using GitHub OIDC—no long-lived AWS access keys are stored in GitHub.
4. Run `/usr/local/bin/deploy-fitness-app <tag>` on the private application instance through AWS Systems Manager.
5. Wait for the command and verify the public HTTPS `/health` endpoint.
6. Publish the release tag and image details in the GitHub deployment summary and AWS Systems Manager Parameter Store.
7. Support manual rollback by redeploying a previously published commit tag.

Terraform creates the AWS role, ECR repositories, instance, networking, secrets, DNS, and HTTPS configuration. After the first `terraform apply`, add the output values as GitHub repository **variables** described in [the infrastructure guide](infrastructure/terraform/README.md).

## Production data and secrets

The release pipeline deploys frontend and backend images; it does not rebuild MongoDB. MongoDB credentials and JWT signing keys are generated by Terraform and stored in AWS Secrets Manager. EC2 instances retrieve only the values permitted by their IAM roles.

Never commit `terraform.tfvars`, Terraform state, saved plans, private keys, database passwords, JWT keys, AWS credentials, or registry tokens.

The running production version is available without EC2 access at `https://<application-domain>/version`. The same metadata is stored in `/fitness-tracker/dev/current-release` in AWS Systems Manager Parameter Store and displayed in the completed GitHub Actions deployment summary.
